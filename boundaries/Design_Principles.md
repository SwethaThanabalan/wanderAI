# wanderAI Design Principles

Version: 0.1.0

Status: Alpha (P0)

---

# Purpose

This document defines the UX and interaction principles that guide the design of wanderAI.

Every screen, interaction, and feature should align with these principles.

If there is a conflict between design decisions, these principles take precedence.

---

# Core Philosophy

wanderAI is not simply an itinerary planner or a navigation app.

It is a travel companion.

The product should help users feel confident, informed, and excited throughout their journey.

---

# Design Principles

## 1. Companion First

Every feature should make users feel like they have a knowledgeable travel companion.

Avoid presenting information without context.

Help users understand:

- where they are
- what comes next
- why it matters

---

## 2. Execute, Don't Plan

P0 focuses on executing an existing itinerary.

The application should optimize for helping users experience a trip—not create one.

Planning is intentionally outside the scope of P0.

---

## 3. Journey Before Destination

The journey itself is part of the experience.

Show interesting places between destinations.

Highlight:

- scenic viewpoints
- cafés
- photo spots
- dog-friendly areas
- rest stops

Users should feel encouraged to explore.

---

## 4. Reduce Cognitive Load

Travel can already be overwhelming.

The interface should answer one question at a time.

Avoid clutter.

Prefer progressive disclosure over showing everything at once.

---

## 5. Keep Users Oriented

Users should always know:

- where they are
- today's progress
- the next destination
- remaining stops

Every screen should reinforce orientation.

---

## 6. Maps Are Context

Maps in P0 provide context.

They help users understand:

- destination order
- route
- nearby highlights

Maps are not used for navigation in P0.

---

## 7. Native iOS Experience

Follow Apple's Human Interface Guidelines.

Use native:

- navigation
- gestures
- typography
- sheets
- animations

Avoid custom interactions unless they significantly improve usability.

---

## 8. Accessibility First

Design for everyone.

Support:

- Dynamic Type
- VoiceOver
- High contrast
- Large touch targets
- Color-independent indicators

Accessibility is a requirement—not an enhancement.

---

## 9. Celebrate Progress

Travel is an experience.

Celebrate:

- completed destinations
- completed days
- completed trips

Progress should feel rewarding without becoming gamified.

---

## 10. Flexible Itineraries

Travel plans change.

The application should embrace flexibility.

Users should feel comfortable:

- skipping stops
- revisiting destinations
- adjusting their pace

The itinerary supports the traveler—not the other way around.

---

# Design Rules

Always:

- Use large imagery.
- Prioritize content over decoration.
- Keep layouts simple.
- Use consistent spacing.
- Minimize taps.
- Support one-handed usage where possible.

Never:

- Overload users with information.
- Force unnecessary interactions.
- Hide important actions.
- Require internet for core P0 functionality.

---

# Future Considerations

Future releases will expand these principles to support:

- AI-assisted planning
- In-app navigation
- Audio tours
- Community features

These additions should strengthen—not replace—the existing travel companion experience.
